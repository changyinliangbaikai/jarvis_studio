# Jarvis Studio v0.4 Acceptance

Version: v0.4  
Positioning: Capability Governance & Context Optimization

## Accepted Capabilities

### Skill Governance

- `/api/skills` scans Runtime Lite skill manifests into a persisted Skill Registry.
- `/skills` shows skill status, version, category, hit count, success rate, average score, tool error rate, and failures.
- `/skills/:id` shows manifest, instruction text, versions, required tools, permissions, selection candidates, matched reasons, and related failures.
- Skills can be enabled or disabled through API actions.
- `/api/skills/:id/test` runs a deterministic Runtime smoke test for the selected Skill and writes an audit record.
- `/skills` exposes a Run Skill Test action and links the resulting Run.
- Runtime emits `skill.registry.loaded` and a v0.4 `skill.select` event with candidates, score, matched signals, conflict flag, injected prompt preview, required tools, and permissions.

### Tool Governance

- `/api/tools` exposes Tool Registry entries sourced from Runtime Lite tool definitions.
- Tool entries include schema, version, category, risk level, default policy, permissions, runtime sandbox, context injection strategy, call count, success rate, output token average, and error rate.
- `/tools` is now Tool Registry.
- `/tool-calls` remains the Tool Call Ledger for execution evidence.
- Tools can be enabled or disabled through `/api/tools/:id/enable` and `/api/tools/:id/disable`.

### Permission Policy

- Runtime evaluates every requested tool before execution through the local permission policy.
- Decisions are emitted as `tool.policy.check` and persisted to `permission_decisions`.
- low risk tools are allowed automatically.
- medium sandboxed tools are allowed by policy.
- high risk tools require approval.
- critical risk tools are denied by default.
- `/approvals` shows the decision ledger and can approve or deny pending decisions.
- Permission policies are persisted in `permission_policies` and can be saved through `POST /api/permissions/policies`.
- Approval, Tool policy, Skill test/status, Context strategy, Permission policy, and Replay snapshot mutations write `audit_logs`.

### Context Budget

- Runtime Context Builder outputs budget strategy, reserved output tokens, total tokens before budget, total tokens after budget, segment priority, segment action, and risk hints.
- Trace import persists v0.4 budget fields on `context_snapshots` and `context_segments`.
- `/context` displays before / after token budget, utilization, segment action, priority, and risk hints.
- `/context-strategies` exposes the default `balanced-v1` strategy and allows JSON updates.

### Failure Diagnosis

- Runtime emits `failure.detected` for permission failures, tool execution failures, and runtime errors.
- Eval failures generate Failure Records with evidence and suggested fix.
- Trace import maps failure events to the `failures` table.
- `/failures` and `/failures/:id` show type, severity, status, evidence, suggested fix, linked run/eval/skill/tool, and support status changes.
- `/api/failures/:id/link-fix` records Prompt / Skill / Tool / Run fix links in the Failure Record.

### Replay Snapshot

- Runtime emits `replay.snapshot.created` for completed or failed runs.
- Trace import persists snapshots in `replay_snapshots`.
- Run detail exposes replay status and actions.
- `/api/runs/:id/snapshot`, `/api/runs/:id/replay`, and `/api/runs/:id/replay-with-overrides` are implemented.
- Replay overrides support Model Provider, Model, Prompt, Skill, Context Strategy, and Tool Policy.
- Snapshot creation copies available input files into `storage/snapshots/<runId>/` and records sha256, size, and missing-file reasons.
- Snapshots intentionally exclude API keys and other provider secrets.

### Experiment Matrix

- `/api/experiments` can create a basic Eval Set x Model Provider x Model x Prompt x Skill x Context Strategy x Tool Policy matrix.
- `/api/experiments/:id/run` creates independent Eval Runs for each variant.
- `/experiments` shows experiment builder, matrix list, best variant, results table, and report export endpoint.
- The matrix is capped at 20 variants to avoid accidental runaway runs.

### Run Detail Governance Summary

- Run detail now includes Skill Debugger summary, Permission Chain distribution, Context Budget summary, Failure count, and Replay Snapshot state before the Trace Tree.

## Verification Evidence

The following gate must pass before claiming v0.4 complete:

```bash
npm run verify:v0.4
```

Current automated coverage includes:

- Runtime governance event test
- Permission Engine high / critical policy test
- Trace import v0.4 governance mapping test
- Existing provider diagnostics tests
- v0.4 governance mutation API tests for Skill test, Tool enable/disable, Permission policy persistence, Failure fix links, and Audit logs
- Existing Eval / Release Gate / Compare / Report workflow tests

## Known Boundaries

- Approvals are persisted decisions; an already paused runtime tool call is not resumed interactively in this version.
- Replay with OpenAI-compatible models resolves secrets through the current provider registry because snapshots do not store API keys.
- Experiment Matrix is the basic version; it creates and aggregates Eval Runs but does not yet provide advanced scheduling or cancellation controls per variant.
