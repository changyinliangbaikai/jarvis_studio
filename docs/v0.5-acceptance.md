# Jarvis Studio v0.5 Acceptance

v0.5 positions Jarvis Studio as an Agent Runtime scenario validation, evaluation, observability, replay, and admission platform. Studio is not the Jarvis Agent itself. Test Tasks in Studio are used to evaluate Agent behavior across model providers, prompts, skills, tools, and context strategies.

## Delivered Scope

- Eval Workspace model and API: CRUD, default model/policy/context settings, file tree, related test tasks and run artifacts. Database table names are preserved.
- Test Task model and API: CRUD, preflight, start, cancel, replay, postflight, events, runs, run artifacts, runtime approvals, and convert-to-eval-case.
- RuntimeAdapter abstraction added. Studio starts Runtime through `RuntimeAdapter`; `LocalRuntimeAdapter` is the first implementation for the local `agent-runtime`.
- EvalTaskRunner orchestration: load Test Task -> preflight -> call RuntimeAdapter -> collect Trace/Run Artifact/Runtime Approval -> postflight -> task status/score writeback. EvalTaskRunner does not implement Agent capabilities.
- Scenario Template model and API: seeded Excel analysis, weekly report, and code review scenarios with preflight/postflight contracts.
- Run Artifact model and API: test task/eval workspace/run/toolCall association, preview, download, mark-final, and final-artifact linkage.
- Runtime Approval model and API: pending/approved/rejected/approved-with-changes status flow backed by the v0.5 `approvals` table.
- Eval Dashboard: `/api/workbench/dashboard` and UI page with test task completion rate, run artifact generation rate, runtime approval pass rate, and preflight/postflight failure rates.
- Test Task Compare: `/api/tasks/compare` and UI page for comparing test task dimensions, run metrics, tool usage, run artifacts, runtime approvals, and postflight checks.
- Runtime tools: `git.status`, `git.diff`, `docx.read`, `docx.write`, `patch.apply`, and `shell.safe_run` are registered in addition to v0.4 tools.
- Weekly report scenario now generates both `weekly_report.md` and `weekly_report.docx` when `docx.write` is available.
- Frontend pages: Eval Dashboard, Eval Workspace, Test Tasks, test task signals, Run Artifacts, Eval Scenarios, Test Task Compare, and Runtime Approval Center.
- Test Task detail API/UI aggregates input, preflight, postflight, runs, trace links, context snapshots, tool calls, run artifacts, runtime approvals, score, and task event logs.
- `packages/agent-runtime` can run independently without starting Studio and remains callable by future `jarvis-cli` flows.

## Local API Smoke

Start the production server:

```bash
npm run start
```

Expected results:

- `GET /api/health` returns `{"status":"ok","version":"0.5.0"}`.
- `GET /api/workspaces` includes `workspace_demo`.
- `GET /api/workbench/dashboard` returns Eval Workspace/Test Task/Run Artifact/Runtime Approval/preflight/postflight rates.
- `GET /api/scenarios` includes `scenario_excel_analysis`, `scenario_weekly_report`, and `scenario_code_review`.
- `POST /api/tasks/compare` with two different test task IDs returns dimension, run artifact, tool, and postflight diffs.
- `POST /api/scenarios/scenario_excel_analysis/preflight` with `workspace_demo` and `input/customer_data.xlsx` returns `status=passed`.
- Creating and starting an Excel test task through RuntimeAdapter returns `202`, then `GET /api/tasks/:id` returns `status=success`, `postflight.status=passed`, and an `analysis_report.md` run artifact.
- Creating and starting a weekly report test task returns `status=success`, `postflight.status=passed`, and both `weekly_report.md` and `weekly_report.docx` run artifacts.
- Runtime-generated run artifacts include `workspaceId`, `taskId`, `runId`, and `toolCallId`, so Test Task detail and Run Artifact Center can trace each output back to the producing tool call.
- A high-risk `shell.safe_run` test task enters `waiting_approval`; approving the pending Runtime Approval resumes the same `currentRunId` and records `run.pause_for_approval` plus `run.resume_after_approval`.
- `GET /api/artifacts/:id/preview` returns report text.
- `POST /api/artifacts/:id/mark-final` returns `isFinal=true`.

## Notes

- `docx.write` is available as a lite-runtime tool. The lite runtime writes a lightweight document artifact at `.docx` paths; full OOXML fidelity is outside v0.5 scope.
- Runtime approval now pauses the active background run in memory and resumes the same run after approval. LocalRuntimeAdapter also exposes an adapter-level `approve()` decision path for direct RuntimeAdapter callers. If the server process restarts while waiting, the fallback `/api/tasks/:id/resume` replay path can still recover from an approved action.
- `patch.apply` and `shell.safe_run` are high-risk tools and default to approval-gated behavior.
