# Jarvis Studio 国际化 (i18n) 设计文档

本文档定义了 `jarvis-studio-web` 中全量中英文国际化的技术设计与实现规范。

## 1. 目标与背景

随着 Jarvis Studio 的升级，其界面中夹杂了许多硬编码的英文词条和中文操作指令。为了提供完整的中英文体验，本设计通过改造现有项目中的 `react-i18next` 模块，对所有 34 个子页面以及主框架进行全量国际化词条提取，并在主界面左下角提供直观的语言切换交互。

## 2. 技术设计

### 2.1 模块化翻译架构（方案 1）

为了避免单一翻译配置文件臃肿，我们采用 TypeScript 模块化组织方式。
在 `src/locales/` 下维护中英文定义，利用 TypeScript 的接口（Interface）和类型推导对 Key 进行强约束。

#### 目录结构

```bash
src/
  ├── locales/
  │     ├── zh.ts       # 中文语言包（作为 Source of Truth 导出 Schema 类型）
  │     └── en.ts       # 英文语言包（继承 TranslationSchema 类型进行全量翻译）
  ├── i18n.ts           # i18next 初始化配置，挂载 zh 和 en 资源
  └── App.tsx           # 框架层逻辑，集成语言切换按钮
```

#### 类型定义 (`src/locales/zh.ts`)

```typescript
export const zh = {
  common: {
    save: '保存',
    cancel: '取消',
    search: '搜索',
    // ...
  },
  // ...
};

export type TranslationSchema = typeof zh;
```

#### 类型定义 (`src/locales/en.ts`)

```typescript
import { type TranslationSchema } from './zh';

export const en: TranslationSchema = {
  common: {
    save: 'Save',
    cancel: 'Cancel',
    search: 'Search',
    // ...
  },
  // ...
};
```

### 2.2 命名空间规范 (Namespace)

为了避免 Key 冲突，所有翻译 Key 划分为以下结构：
* `common`: 通用操作、按钮、网络状态（如 `save`, `cancel`, `loading`, `success`, `error`）。
* `nav`: 侧边栏和主导航菜单 Key。
* `shell`: 侧边栏顶部、底部以及公共 Header 的词条。
* `pages`: 页面私有词条。根据页面文件名映射子命名空间（如 `pages.agents.*`, `pages.playground.*`）。

### 2.3 动态插值规范

包含动态变量的翻译一律采用插值：
* **定义**:
  * `zh.ts`: `common: { saved: '{{name}} 已保存' }`
  * `en.ts`: `common: { saved: '{{name}} saved' }`
* **使用**: `t('common.saved', { name: selected.name })`

### 2.4 侧边栏语言切换 UI

在 `App.tsx` 侧边栏底部（主题切换按钮左侧）添加语言切换按钮：
* **图标**: 使用 `lucide-react` 中的 `Globe` 图标。
* **动作**: 点击触发 `i18n.changeLanguage(i18n.language.startsWith('zh') ? 'en' : 'zh')`。
* **样式**: 配合原有的 `.theme-toggle`，新增 `.lang-toggle` 样式，拥有平滑的旋转或缩放过渡效果。

## 4. 验证计划

1. **类型校验**: 运行 `npm run build` 或 `tsc --noEmit`，验证 `en.ts` 翻译字典是否完全对齐 `zh.ts`，杜绝漏配的 Key。
2. **切换验证**: 启动本地服务，通过点击左下角的地球仪按钮，验证侧边栏、所有核心页面的词条是否均能在中英文间实时切换。
3. **样式响应**: 确保英文版本字符长度增加后，表格、表单和侧边栏的布局依然保持美观（无溢出、无截断）。
