# Jarvis Studio v0.3 测试方案

## 1. 测试目标

验证 Jarvis Studio v0.3 能形成完整质量闭环：

```text
Dataset 导入 -> 真实 Runtime 批量执行 -> 自动评分 -> 人工复核
-> 回归对比 -> Release Gate -> Markdown Report
```

测试必须证明数据可追溯、结果可重复、失败可分类、成本可统计，以及所有页面能完成对应操作。

## 4. 运行时闭环验收

使用 Deterministic Local Provider 执行 Smoke Dataset：

1. 运行 `npm run seed`。
2. 在 Eval Bench 创建 `jarvis_smoke_v1` Eval Run。
3. 启用 LLM-as-Judge，`max_parallel=2`。
4. 等待状态变为 `completed`。
5. 核对 5 个 Case Result 均有真实 Run Trace、规则评分和 Judge JSON。
6. 执行 Release Gate。
7. 对任一 Case Result 保存人工 Review。
8. 生成并下载 Markdown Report。
9. 再执行一次相同 Dataset，在 Compare 页面比较两次 Eval Run。

预期：

```text
Smoke Dataset: 5 cases
Pass Rate: 100%
Rule Score: 每个结果均有
Trace: 每个结果均关联 run_id
Gate: PASS
Report: 可生成并下载
```

## 5. 云模型与成本验收

对一个配置了价格的 OpenAI-compatible Provider 执行单个 Smoke Case：

1. 配置 input/output price per 1M tokens 和 currency。
2. 测试连接成功后创建单 Case Eval Run。
3. 核对 `llm_calls.cost`、Case Result cost、Eval Run total cost。
4. 核对 API 和日志中均无明文 API Key。

成本公式：

```text
prompt_tokens / 1,000,000 * input_price
+ completion_tokens / 1,000,000 * output_price
```

## 6. UI 手工验收

| 页面 | 验收操作 |
| --- | --- |
| Eval Datasets | 展示版本、case 数、最近结果；导入和重新加载 |
| Eval Cases | Dataset/priority 筛选；查看契约；单独运行 |
| Eval Runs | 创建、轮询状态、取消、重新评分、进入详情 |
| Eval Run Detail | 查看聚合指标、失败标签、Case Results、Gate |
| Case Result Detail | 查看输入/期望/输出/规则/Judge；保存 Human Review |
| Compare | 选择 baseline/candidate；查看总体和 case 级 diff |
| Release Gates | 导入 YAML；对 Eval Run 执行 Gate |
| Reports | 生成、重新生成、下载 Markdown |
| Model Providers | 配置输入/输出价格和 currency |
