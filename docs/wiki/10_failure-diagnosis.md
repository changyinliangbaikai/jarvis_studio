# 故障诊断与归因闭环使用指南

智能体（Agent）由于执行步骤多且依赖大模型生成，容易在运行中发生各种偶发性或系统性异常。快速捕捉故障、进行根因定位并跟踪其修复状态，是智能体质量保障的关键。

Jarvis Studio v0.5 提供了 **故障诊断中心 (Failures)**，实现了异常的自动捕获与“修复链路归因”闭环。

---

## 1. 自动故障检测与触发 (Failure Detection)

每当智能体在后台或评测中发生异常时，运行时会立刻抛出 `failure.detected` 异常事件。

### 1.1 触发故障的五大场景
系统会自动捕捉并记录以下异常为 **Failure Record (故障记录)**：
1. **预检 (Preflight) 失败**：测试任务启动前，预检合约校验不通过（例如输入所需的 workbook 或源文件不存在、格式不匹配或缺失必要的配置），系统自动判定为预检失败并生成故障记录；
2. **后检 (Postflight) 失败**：测试任务运行结束后，后检合约断言未通过（例如生成的文件不存在、输出结果未通过关键字审计等），系统自动判定为后检失败并生成故障记录；
3. **权限引擎拒绝**：工具调用因超出安全策略、或被管理员点击 **Deny** 拦截，触发权限拒绝并挂起中断；
4. **工具执行崩溃**：工具内部执行出错（例如 Python 代码语法报错）或 `shell.safe_run` 等脚本执行超时被强行杀死；
5. **评测预期未满足**：在回归评测中，用例的 Expected 条件（如必须包含的文本或必须生成的产物）未能被 Agent 满足而导致用例不通过。

## 2. 故障诊断大盘 (Failures Dashboard)

进入 `/failures` 页面，您可以看到整个项目的异常情况汇总。

### 2.1 诊断面板字段解析
点击任意一条故障记录，可查阅其深度诊断详情：
- **故障类别与严重程度**：分为 `high`、`medium`、`low`，并标记状态（`pending` 待排查、`investigating` 排查中、`fixed` 已修复）；
- **错误证据 (Evidence)**：收集故障发生时的最直接物理证据。包括工具报错的 stderr 堆栈日志、模型的输出内容或系统校验异常信息；
- **智能修复建议 (Suggested Fix)**：系统根据报错类别，自动计算出排障指引。
  - *例 1（权限错误）*：`Suggested Fix: 权限拦截。该工具为高危类型，请前往 /approvals 面板批准该操作，或在 Tool Registry 中微调该工具策略。`
  - *例 2（超时错误）*：`Suggested Fix: 执行超时。请检查脚本 .jarvis-runtime/prepare-analysis.py 是否陷入死循环，或使用 shell.safe_run 执行并放宽超时预算。`

## 3. 关联修复闭环机制 (Link-Fix)

在传统的排障中，开发者修复完 Prompt 或代码后，故障记录通常处于断联状态。v0.5 引入了 **Link-Fix (关联修复)** 机制，将故障与修复手段进行彻底绑定归因。

```text
               自动捕获 failure.detected
                           │
                           ▼
                  进入故障诊断详情页
             (查看 Evidence 堆栈与 Suggested Fix)
                           │
                           ▼
                   开发者修改提示词/技能
                           │
                           ▼
                点击 [Link Fix (关联修复)]
       ┌───────────────────┼───────────────────┐
       ▼                   ▼                   ▼
[关联 Prompt 版本]    [关联 Skill 更改]    [关联成功 Run ID]
标记改动后的提示词版    标记改动的技能 manifest  标记修复后验证成功的 Run
                           │
                           ▼
                 故障状态自动流转为 Fixed
                    形成质量归因闭环
```

### 3.1 关联修复操作步骤
1. 开发者在阅读 Suggested Fix 建议后，在本地进行修复（例如：更新了 Prompt v0.5 模板以避免模型少调用工具，并在控制台重新运行验证成功）；
2. 返回 `/failures/:id` 故障详情页，点击右上角的 **Link Fix (关联修复)** 按钮；
3. 在弹出的归因输入框中，您可以填写并关联本次修复所产生的具体实体：
   - **Link Prompt**：关联本次修改后产生的最新提示词版本（如 `excel-analysis@v0.4`）；
   - **Link Skill / Tool**：关联修改过的技能 Manifest 或工具；
   - **Link Verification Run**：关联验证此次修复成功、已跑通的全新 **Run ID**。
4. **状态流转**：关联成功后，该故障记录的状态会自动更新为 **`Fixed (已修复)`**，并保存关联实体的链接。

---

## 4. 故障归因看板
在故障大盘的顶部：
- 统计当前未修复的故障总数与级别分布；
- 统计哪些工具或技能是“故障高发区”（为您重构 Agent 提供重点优化方向）；
- 展现从故障发生到最终标记为 `Fixed` 的平均修复周期，全面度量团队开发 Agent 的响应时效。
