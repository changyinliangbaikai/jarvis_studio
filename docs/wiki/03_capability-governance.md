# 能力治理与安全审批操作指南

在企业级 Agent 工程实践中，智能体拥有对文件、代码甚至 Shell 的调用能力。为了确保智能体运行在安全边界内，Jarvis Studio v0.5 提供了全套的 **Skill/Tool 治理注册表**、**本地权限校验引擎** 以及**流式挂起恢复审批中心**。

---

## 1. 技能与工具治理表

系统将所有智能体可能使用的元数据进行集中监控：
- **Skill 注册表 (`/skills`)**：扫描技能 Manifest 描述、Hit 命中次数、成功率及关联的故障日志，支持在线 Enabled / Disabled 一键封锁。
- **Tool 注册表 (`/tools`)**：列出每个工具的 Schema 参数校验、沙箱类别、安全等级（Risk Level）、以及平均消耗的 Token 大小。

### 1.1 v0.5 新增的高危工具成员
在 v0.5 中，系统进一步扩充了对环境进行修改的危险工具：
- **`shell.safe_run`**：在受限的工作空间路径下，安全拉起本地系统命令；
- **`patch.apply`**：大模型生成代码修改补丁（Diff）后，在本地执行自动打补丁操作。
- *注：这两个工具属于高危等级，默认会触发权限拦截与挂起审批流。*

---

## 2. 流式挂起恢复审批流 (Pause & Resume) `[v0.5 重大升级]`

在旧版本中，发生权限拦截通常是“一票否决”直接终止任务。**在 v0.5 中，Jarvis Studio 引入了领先的“内存流式挂起与恢复运行”机制**：

```text
               Agent 触发高危工具 (如 shell.safe_run)
                                 │
                                 ▼
                     [权限策略引擎拦截判定]
                                 │
                                 ▼
        任务不被终止！而是暂停执行，挂起当前运行内存 (State)
             同时向 Studio 发送 run.pause_for_approval 事件
                                 │
                                 ▼
              进入 /approvals (运行时审批中心) 审查
                                 │
         ┌───────────────────────┼───────────────────────┐
         ▼                       ▼                       ▼
   [Approve (放行)]    [Approve with Changes]    [Rejected (拒绝)]
 允许执行原入参，系统    修改大模型生成的工具参     直接拒绝，引擎向 
 发送 resume 事件，在    数，并在修改后恢复放行。    Agent 回注权限拒绝
 原内存进程下无缝恢复。          │                       错误并继续运行
         │                       │                       │
         └──────────┬────────────┘                       ▼
                    ▼                              Agent 收到 
               工具开始执行                        Permission Denied
```

### 2.1 内存挂起 (Pause)
当策略引擎扫描到高风险工具调用时，智能体运行环境被**流式挂起**。系统会在 `audit_logs` 审计表中记入该操作，并在页面上将任务状态标识为 `waiting_approval`。

### 2.2 审批决策流 (Approvals)
在 **Runtime Approval Center**（审批中心）页面，管理员可以并行审查所有的 Pending 审批。可以做以下三类操作：
1. **Approve (通过)**：点击通过，系统会下发 Resume 信号（发出 `run.resume_after_approval` 事件），**使用同一个 `currentRunId` 在挂起的原内存进程下继续向后运行**，保证了多步交互的连贯性。
2. **Approve with Changes (参数改动通过)**：支持管理员在页面上**直接修改大模型编造的工具入参**（例如：模型由于幻觉写错了文件名，管理员在线订正为正确路径），然后再放行恢复。
3. **Reject (拒绝/驳回)**：拒绝本次调用，直接向 Agent 运行时注回 `Permission Denied` 异常，Agent 会在剩下的 Token 预算内尝试其他备用路径。

### 2.3 异常重启 Resume 恢复保障机制
- **问题场景**：如果服务器在挂起等待管理员审批期间意外发生了进程重启或断电，内存中的挂起状态将丢失；
- **恢复策略**：v0.5 后端提供了 `/api/tasks/:id/resume` 接口。系统会检测当前任务关联的物理 Replay 快照，解析历史事件日志，自动在后台流式回放并重新建立内存上下文，直到恢复到被批准的那一步骤继续运行。这提供了工业级的可靠性保障。
