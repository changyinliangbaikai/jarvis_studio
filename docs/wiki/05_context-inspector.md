# 上下文探针与预算优化指南

在大模型调用中，随着对话轮次的增加以及长文件的注入，Prompt 很容易突破大模型能容纳的 Token 窗口，或导致 API 计费成本呈指数上升。

Jarvis Studio v0.5 提供了 **上下文预算控制引擎** 和 **策略编辑器**，对输入 Prompt 实行精细化的预算分配与状态诊断。

---

## 1. 什么是上下文预算控制 (Context Budget)？

在系统运行中，每一次 LLM 调用前，运行时都会通过 **Context Builder**，结合当前激活的**上下文策略**，对所有的 `Context Segment` 进行实时的 Token 计算与裁剪动作分流。

### 1.1 上下文策略编辑器 (Context Strategies)
- **管理入口**：在页面导航进入 **Context Strategies**。
- **默认策略 `balanced-v1`**：系统默认注入该策略配置文件（支持在线修改并保存为自定义 JSON）。
- **统一配置文件**：在 v0.5 中，策略数据除了持久化在 SQLite 中外，还会被安全地写入项目根目录的 **`configs/context-policy.yaml`** 文件中，实现全局的配置持久化与版本管理。
- **策略参数**：
  - **最大上下文预算 (`maxContextTokens`)**：例如限制单次输入最多 32,768 个 Token；
  - **保留输出 Token 预算 (`reservedOutputTokens`)**：为模型生成回复预留的空间（如 2,048 个 Token）；
  - **片段优先级与行为映射**：规定哪些类型的片段（如系统指令、最近一轮工具结果）属于不可裁剪的 `P0` 级别，哪些（如较久的历史对话、文件原文）在超限时执行压缩或截断。

## 2. 上下文诊断看板核心功能

当您在 Trace 详情或运行列表中点击查看 **Context Snapshot (上下文快照)**，即可进入探针分析界面：

```text
┌────────────────────────────────────────────────────────────────────────┐
│ [Token 预算看板]                                                        │
│  预算前总 Token: 42,180   ───► [预算控制引擎] ───►  实际总 Token: 18,600  │
│  预算额度: 32,768 (利用率: 56.7%)                   节省 Token: 23,580 │
└────────────────────────────────────────────────────────────────────────┘
┌────────────────────────────────────────────────────────────────────────┐
│ [Segment Action 诊断区]                                                 │
│ 🔘 system_prompt   (base-agent)       1,200 Tokens  [Keep]       (✔)   │
│ 🔘 skill_instruct  (excel-analysis)   2,600 Tokens  [Keep]       (✔)   │
│ 🔘 file_content    (customer.xlsx)    8,200 Tokens  [Compress]   (✔)   │
│ 🔘 prev_history    (history_turn_1)   4,800 Tokens  [Truncate]   (✔)   │
│ 🔘 retrieve_memo   (old_memory)       3,500 Tokens  [Drop]       (✖)   │
└────────────────────────────────────────────────────────────────────────┘
```

### 2.1 预算前后 Token 可视化对比
- 看板顶部会并排展示**控制前的 Token 大小**、经过策略引擎处理后的**实际发送 Token 大小**、以及节省比例与当前的预算利用率。
- **作用**：让开发者一眼洞察是哪一部分策略起到了明显的瘦身效果。

### 2.2 裁剪动作 (Segment Action) 追溯
列表中每一个 Segment 片段都会被贴上由引擎自动算出的裁剪动作标签（Action）：
- **`keep`**：完整注入模型，未做任何删改。
- **`compress`**：该片段（如长文本原文）在注入前被运行时自动执行了摘要或语义压缩，节省了 Token。
- **`truncate`**：由于超出预算上限，本片段（常见于多轮对话历史）的部分较旧内容被强行剪切截断。
- **`drop`**：本片段优先级过低，在预算吃紧时被**完全抛弃**，未能包含在本次 Prompt 中（在 `included` 栏会显示为红叉 ✖）。

## 3. 风险警示机制 (Risk Hints)

如果只是硬性地把上下文剪裁掉，极易引起大模型失忆、不遵循系统指令或因缺失前一步的工具执行结果而产生严重幻觉。

为此，Jarvis Studio 探针界面引入了 **Risk Hints (风险提示)** 机制：
- **触发逻辑**：当策略引擎在裁剪时，如果发现**高优先级的关键 Segment** 被执行了 `truncate` 或 `drop`（例如，上一轮的 `tool_result` 工具执行结果被抛弃，或 `system_prompt` 被裁剪），系统会在该片段右侧弹出**高亮的风险警示标签**。
- **警示示例**：
  > ⚠️ **高风险**：上一轮的工具执行结果 (tool_result) 已被丢弃！大模型将无法感知前一步的 xlsx.inspect 已经成功读取，可能会导致重复调用工具或任务崩溃。
- **调试行动指南**：
  当您在分析 Runs 失败原因时，如果看到有相关的风险警示，请立即前往 **Context Strategies** 调整默认策略中各片段的优先级权重，或者提升该技能的 Token 上限，实现上下文的精细化优化。
