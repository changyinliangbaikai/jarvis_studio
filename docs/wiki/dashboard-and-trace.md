# 运行监控与 Trace 调试指南

在智能体开发中，“黑盒”执行是调试的最大痛点。Jarvis Studio 提供了 **Runs (运行监控)**、**Trace (轨迹追踪)** 与 **Run Compare (运行记录对比)** 视图，让您能够流式捕获 Agent 执行过程并进行深度分析。

---

## 1. Runs 看板 (运行记录列表)

Runs 看板是所有 Agent 执行轨迹的集中注册表。每一行代表一次独立的运行生命周期。

### 1.1 核心指标定义

在 Runs 列表中，您可以实时监控并筛选以下指标：
- **运行名称/Session**：此记录所属的项目任务与多轮对话线程。
- **状态 (Status)**：包含 `running`（进行中）、`success`（成功）、`failed`（失败）和 `cancelled`（取消）。
- **配置绑定**：展示本次运行所使用的模型（Model）、当前选中的 Skill 以及 Prompt 版本。
- **总耗时 (Latency)**：以毫秒为单位统计本次任务执行的总时长。
- **Token 消耗**：精确统计 Prompt 占用的 Token、大模型生成回复的 Token 以及总消耗。这是精细化评估运行成本的关键。
- **工具调用数**：记录 Agent 尝试调用了多少次底层 Tool。
- **产物数量 (Artifacts)**：统计该 Run 在运行中输出并落盘的业务文件总数。
- **评分 (Score)**：如果该 Run 属于批量评测用例的 Mock 运行或跑过规则打分器，这里将直接显示其评分（满分通常为 5 分）。

## 2. SSE 实时事件流与 Trace Tree 调试

点击任意一个 Run 的名称，即可跳转进入其 **Trace (轨迹追踪) 详情页**。该界面采用“左树右表”的双栏设计：

### 2.1 Server-Sent Events (SSE) 实时流渲染 `[v0.2]`
在 v0.2 中，当您在控制台运行智能体、或在评测工作台启动用例时：
1. 后端会开启一个 SSE 数据流通道：`GET /api/runtime/runs/:runId/events`；
2. 随着 Agent 在后台的逐步执行，每一次状态的演进（如开始构建上下文、开始 LLM 请求、启动外部工具、写出产物等）均会以毫秒级的速度流式推送到前端；
3. **动态生长**：页面无须手动刷新，左侧的 **Trace Tree** 会流式动态“闪烁、生长、更新”，并在节点上呈现当前的加载状态；
4. 右侧面板会跟随左侧当前执行的最深子 Span 自动滚动展示入参和模型输出，为您呈现实时的“心电图式”可观测性。

### 2.2 Trace Tree 树形图交互
- **展开/折叠**：点击父级节点（如 `Turn 1` 或 `llm.call`）左侧的小箭头，可以折叠其下的子 Span，从而在大规模复杂流程中快速隐藏无关干扰项。
- **跳转追踪**：点击树状图中的任意一个节点，右侧详情面板将即时同步更新为该节点的具体物理参数。

## 3. Span Detail (节点详情) 面板解析

不同类型的 Span 节点，其详情面板中展示的侧重点完全不同。主要核心节点类型说明如下：

### 3.1 `llm.call` (大模型调用)
详细展示模型的输入 Prompt（或 Context Snapshot ID 相对链接）、参数设置（如 `temperature`），以及深度耗时指标：
- **首 Token 延迟 (TTFT)**：即 `firstTokenLatencyMs`，反映模型的 Prefill Prefetch 响应速度。
- **解码速度 (TPS)**：即每秒生成的 Token 数（`tokensPerSecond`）。
- **生成分布 (Prefill & Decode)**：分析在 Prompt 上下文预加载（Prefill）和流式输出（Decode）上分别耗费的时间，精准定位瓶颈在大模型处理长上下文还是长输出。
- **模型输出 (Output)**：包括大模型的思考内容，以及结构化的工具调用（`toolCalls`）声明。

### 3.2 `tool.call` (工具调用)
展示 Agent 触发外部环境交互时的物理静态/动态链路：
- **调用原因 (Reason)**：模型为什么决定使用这个工具。
- **参数 (Arguments)**：传递给工具的 JSON 输入参数。
- **权限与审批**：包含所需权限列表、用户（或系统）是否批准、以及审批模式（自动 `auto` 或手动人工 `manual`）。
- **执行结果与日志**：工具执行的状态码（`exitCode`）、成功标志、以及标准输出（`stdout`）/标准错误（`stderr`）日志文件的相对路径。
- **上下文回注 (Context Injection)**：该工具结果是否会被完整或以摘要（Summary）的形式注回下一次模型调用的上下文中，注入了多少 Token。

### 3.3 `artifact.write` (写入产物)
展示 Agent 此次运行所创造的文件产物卡片：
- 文件类型（如 `xlsx`, `pdf`, `markdown`, `json`）。
- 文件的物理生成路径。
- 文件的大小（Bytes）及用于防篡改的 SHA-256 校验和。

## 4. Run Compare (运行记录对比) 页面 `[v0.2]`

为了快速验证单次优化改动的真实差异（例如：微调 Prompt 模板前后的执行轨迹差异），v0.2 引入了 **Run Compare (运行记录对比)** 视图：
1. **并排对比**：允许您勾选任意两次 Run 并排进行指标对比；
2. **比较细节**：系统将高亮列出两次运行在以下维度的核心差异：
   - 绑定的模型、Prompt 和激活的 Skill；
   - 工具链执行顺序（Tool Chain）的异同；
   - Latency（总延迟）和 Token 消耗的差异对比；
   - 客观回归得分的增减；
   - **响应 Diff (Output Diff)**：并排比对大模型最终输出的文案内容；
   - **变更账本 (Change Ledger)**：自动输出一份变更总结清单，指导开发人员直观判断优化是否达到准入条件。

## 5. Conversation Replay (多轮对话回放)

除了底层的 Trace Tree 以外，如果您想从偏业务的角度整体复盘交互，可以使用 **Sessions -> Conversation Replay (对话回放)** 页面：
1. 系统将滤除无关的细碎底层 Span，仅以人类友好的聊天气泡重塑每一轮对话；
2. 用户消息与 Agent 最终输出将以明显的样式左右分栏排列；
3. 在连续的对话响应气泡中间，系统会交互式地插入**折叠的工具调用小卡片**（展示工具名、简短参数与执行成功状态）与**产物生成标签**。点击它们可随时展开查看当时环境发生了什么。这提供了一种高可读性、高聚合度的业务逻辑回溯体验。
